# Product behavior

This is a single-account, session-only TOTP generator. It does not enroll accounts, retrieve secrets, validate sign-ins, provide a password vault or import counter-based HOTP. A service must supply the shared secret and accept the generated code.

Typing updates after a 200 ms pause. Any edit clears the previous result and disables copy immediately. IME composition is not parsed. Field errors appear on blur or Enter and remain beside their controls. Settings are collapsed initially. Clear resets inputs, errors, settings, account label and code without persisting user data.

Base32 accepts lowercase, spaces, line breaks and hyphen grouping. It validates the alphabet, complete byte lengths, optional padding and unused trailing bits. Inputs are bounded to 8192 characters and decoded Base32 material to at most 1280 bytes. A URI must identify `totp`, a secret, supported options and a decodable label. Duplicate recognized parameters, conflicting issuer labels, credentials, fragments and HOTP are rejected. Unknown URI parameters are ignored and never fetched. The label is shown only inside collapsed technical details using textContent.

URI edits import algorithm, digit count and period and reset clock adjustment to zero. Subsequent setting edits override imported settings for this session. Raw-key edits keep selected settings. Periods must be integer seconds from 1 to 300, with a default of 30. The clock adjustment ranges from -300 to 300 seconds and defaults to zero. Positive values advance the effective clock. There is no remote time synchronization.

Enter recalculates from the current form without reimporting unchanged URI settings. A new URI edit is imported even when Enter is pressed before the typing delay finishes. The eye button sits beside the secret field, keeps a localized accessible action name and pressed state, and works with keyboard and touch. Clear returns the field to its masked state. Key entry is a text field with autocomplete off and CSS visual masking, rather than a new-password field. The supported engines implement the masking property. Browsers without that property fall back to a native password input with autocomplete off. Visual masking does not prevent a privileged extension or assistive technology from accessing the value.

Share key is disabled until the current key and settings produce a valid calculation. It opens a panel with a credential warning, a readonly link and an explicit Copy link action. The link uses `#totp=1&secret=...&algorithm=...&digits=...&period=...`. It carries a canonical unpadded Base32 key, supports the same algorithm/digits/period bounds as manual entry, and omits account labels and device clock adjustment. Editing any generation input, Clear, tab hide and page exit remove the exported link and cancel stale share status. Copy is not automatic and no native share service is invoked.

Opening a supported link imports the key and settings and resets device clock adjustment to zero. Initial shared locale selection runs first so the fragment survives a required locale redirect. The final page removes a recognized share fragment from its current history entry before validating/importing it, and removes it from the reciprocal language link. A recognized malformed link is also removed and reports a local error without starting calculation. Other section fragments are left intact. Query-string keys and other products' link formats are unsupported. Fragment removal does not guarantee erasure from history/sync, clipboard, messages or other copies. Returning through a shared link again intentionally starts another session. Reloading the scrubbed page does not restore the key.

The counter is an unsigned eight-byte big-endian integer. Web Crypto imports a nonextractable HMAC key, then dynamic truncation and decimal padding produce the code. The timer checks absolute wall-clock time every 200 ms. At a time-window change the old code disappears before the new asynchronous calculation. Copy computes a current code again and rejects outdated asynchronous work. When a tab hides, output and imported key references are cleared. Returning recomputes from the form. Leaving, BFCache restoration and reload reset the session.

The browser uses the device's Unix time. A rejected code may mean incorrect settings or a wrong device clock. The verifier decides its acceptance window and must prevent reuse after successful validation. The client cannot establish that a code was used once.

The main input accepts a Base32 key or an otpauth://totp/ setup URL. A pasted URL is parsed locally and is never fetched. The QR import disclosure accepts a local PNG/JPEG/WebP/GIF image. Its styled file trigger opens the browser file dialog. A dashed blue intake surface contains a labelled editable textarea for images or setup URLs through native paste, including Ctrl+V and phone keyboard Paste, and accepts drag/drop. Text delivered through input instead of ClipboardEvent is also parsed after a short debounce. The field is visually masked and cleared after import/cancellation/reset. Image paste depends on browser/keyboard support and has a file-selection alternative. Multiple clipboard files are rejected. No clipboard-read API or permission prompt is used. Images are decoded on the device by the bundled reader. A separate camera action requests video permission only after a click, shows a local muted preview, and uses the same decoder. All camera tracks and pending decoding stop on success, error, Stop/Escape, reset, edits, disclosure close, tab hide, page exit and a two-minute scanning deadline. Late permission after cancellation is discarded with its tracks stopped. Exactly one valid TOTP setup is required. Imported settings reset clock offset to zero and the key returns to masked presentation. Unknown, HOTP, migration and multiple-code payloads have nearby errors. Failed or cancelled scans preserve the previous manual key; concurrent edits, reset and backgrounding cancel obsolete work. Read the limits and privacy boundaries in SECURITY.md.

Control inventory includes a visually masked text input and reveal button, text inputs with mobile numeric keyboards, a readonly share-link textarea, five native radio controls presented as selection cards, styled native progress, native disclosures, buttons, a hidden native file input with styled trigger, a visually masked QR paste textarea in a styled intake area, a camera action/preview, a cancel-import or Stop camera action, language links and a theme switch. Algorithm and code-length cards use the shared blue selection background without a duplicate radio circle. The native inputs retain label activation, arrow-key selection, disabled behavior and a visible card focus outline, including forced colors. Dropdowns, calendars, color pickers, range sliders, popup panels and checkbox controls are NOT_APPLICABLE. Do not add these solely to satisfy a generic inventory.
