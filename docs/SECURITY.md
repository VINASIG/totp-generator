# Privacy and security boundaries

Normal secret entry never enters HTTP request URLs, forms, analytics, logs or persistent application storage. Explicit share links contain the secret in the URL fragment. Fragments are not part of the HTTP resource request, but they are credentials and can be exposed by browser history/sync, extensions, clipboard, messages or a compromised device. Only finite theme/language preferences use shared Secure cookies or local fallback under WEB-011. Tests use public RFC and synthetic secrets. Rendering uses textContent/value, so imported labels cannot become markup. Provisioning URI contents are never followed. Setup URLs are parsed locally as data, never requested as web resources.

## Credential-bearing links

The owner selected immediate code generation on opening a link and accepted its credential value. This implementation does not claim encrypted sharing. Combining ciphertext and its decryption key inside one link would not protect against a link holder. Confidential sharing against a compromised link channel would require a separately authenticated or separately delivered secret, which is a different interaction.

Only an explicit Share key action exposes a link. Copy link is a separate action beside a readable warning. All generated credential data goes after `#`, without account/issuer labels or the sender's clock adjustment. No shortening service, QR tracking endpoint, web share target, backend or runtime dependency is added. A supported incoming fragment is removed with history.replaceState before validation/import into the final locale page. Language redirects can carry the fragment within the same origin before removal. Removal also clears the reciprocal language link. Recognized invalid fragments are scrubbed and fail closed. Scripts unavailable or blocked before initialization cannot scrub a URL. Invalid query links may already have sent their query to a server before any JavaScript and are not supported. Never put a real key in a query manually.

The v1 parser rejects duplicate, missing and unexpected fields, unsupported versions, malformed/noncanonical Base32, unsupported algorithms/digits/periods, and fragments longer than 2304 characters. Secret bounds match the existing provisioned-key parser. Error messages and verification records exclude imported values. Export strings and stale share callbacks are dropped on edits, reset, tab hide and page exit. There is no expiry, one-time enforcement or recipient access control in a static bearer link. Recipients can retain a key indefinitely. Revocation requires replacing the TOTP key at the original service.

URL removal and volatile state are exposure reductions, not secure deletion or a guarantee that the browser, host page, extensions or clipboard manager are safe. CSS key masking is visual only and is not encryption or a protected input guarantee for every assistive technology. The field does not use new-password semantics. Autocomplete off is a request to the browser, not an exclusion of all password-manager extensions.

The production build installs CSP using exact inline-script hashes. The credential-holding document allows same-origin connections for self-hosted decoder assets and denies external Fetch connections, frames and form submissions. Scripts, styles, fonts and ordinary images are self-hosted. Controlled data SVG masks and local raster blob URLs are permitted by img-src. Worker-src permits blob workers, which inherit the document's policy. The bundled QR worker uses wasm-unsafe-eval for WebAssembly, without allowing JavaScript eval. A no-referrer meta field suppresses referrers on navigation. HMAC still uses Web Crypto without an OTP dependency. QR reading uses the locked zxing-wasm reader, with its default CDN locator explicitly replaced by a same-origin WASM asset.

## QR image import

Local image bytes from files or user-initiated paste are never uploaded. Native QR paste reads only the data supplied by the paste event. The Paste image button reads image contents only after an explicit click. It never polls the clipboard or requests text/HTML data. Permission denial or missing capability preserves keyboard paste and file selection. Revision checks discard late clipboard responses after another source, edit or clear. Keyboard-provided text input is parsed locally and transient paste values are cleared. Only a single validated otpauth TOTP payload is imported. Arbitrary URLs and text, HOTP, invalid options, migration exports and multiple QR symbols are rejected rather than navigated or guessed. The existing strict parser validates a candidate before it replaces the manual field. A failed scan preserves the previously entered key and resumes its calculation. Starting a scan clears the visible old code and share link until completion. Manual edits, settings changes, cancellation, Clear, tab hide and page exit abort pending work. Revision checks prevent a stale scan from overwriting newer input.

Files are checked by magic bytes rather than a trusted MIME/filename. SVG/HTML and unsupported formats are rejected. PNG/GIF header dimensions are checked before image decode; JPEG/WebP dimensions are checked after the browser decoder. Images are bounded to 24 million pixels and 12,000 pixels per side, then reduced to a 4096-pixel longest side for QR reading. These are workload limits, not proof against every browser image-decoder vulnerability or temporary allocation. Browser decoding is followed by a white-composited Canvas raster and a bounded QR worker. Canvas buffers, blob URLs and workers are released on completion/cancellation. Worker pixels are zeroed after decoding, but JavaScript/browser image internals cannot be securely erased. Uploaded images and decoded QR text are not previewed or persisted. Animated input reads a browser-selected initial frame rather than scanning every frame.

Camera scanning calls getUserMedia only after an explicit scan action, with audio false and ideal rear-facing video. A local, muted, inline preview shows the active camera. There is no MediaRecorder, remote peer connection or frame upload. Frames are downscaled to a 1280-pixel longest side and sent sequentially to one decoder worker for that scan session, with a pause between reads and no queue. Each decode has the same 15-second worker limit. The camera has a two-minute deadline after access is obtained. All tracks stop, srcObject is detached and the worker terminates on success, error, Cancel/Escape, edit, reset, disclosure close, tab hide or page exit. If permission arrives after cancellation, the newly delivered stream is stopped before use and cannot import a key. The browser's permission decision cannot be revoked by this page; cancelling a pending request prevents later use. Unsupported browsers and permission/device failures have local errors and retain manual entry/file import.

Revision guards stop stale asynchronous calculations and clipboard status from reappearing after edits or reset. An expired code is cleared before another HMAC result arrives. Copy recalculates at the current time. Input bytes are zeroed after key import. Nonextractable CryptoKey references and displayed output are dropped on tab hide and page exit. JavaScript strings, browser input state, operating-system clipboard history and browser extensions cannot be securely wiped or excluded by this application. Use a trusted device.

The verifier still controls throttling, token enrollment, recovery, acceptance windows and replay prevention. This generator has no server verification endpoint. It cannot know whether a code has been used or whether a device clock matches the server. HTTPS and a Web Crypto-capable browser are required. Script failure leaves controls disabled with readable guidance.

## Dependency review

On 5 October 2026, npm audit reported seven high-severity entries all derived from the build-only Stylelint glob chain and [the braces recursion advisory](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm). The registry and advisory list no patched braces release. This chain is absent from the browser bundle and is not fed user secrets or remote file patterns. Stylelint uses fixed authored patterns over local project CSS. Untrusted PR code is not run with repository secrets, and the deploy job requires verified main.

The warning remains recorded rather than hidden or downgraded to an obsolete linter. Runtime-only npm audit must pass with no known vulnerabilities. Review this build-tool finding when a patched compatible dependency is published. This is a scoped dependency assessment, not a penetration test or proof that browser extensions and host devices are safe.
