# Verification coverage

QR import tests use generated public RFC credentials rather than real enrollment images. The production image decoder, clipboard image/setup-URL paste events, mobile-style text input delivery and pasted otpauth setup URLs are exercised in all three engines. Checks cover official expected OTP output, imported settings, masked input, rejection of non-TOTP/duplicate/migration/multiple/empty QR payloads, image type/dimension/byte limits, no secret requests or upload, missing decoder assets, cancellation, concurrent manual edits, reset, backgrounding and timeout. Open-disclosure layouts and field-local errors cover both locales/themes, breakpoint neighbors and 200% text. Controlled browser evidence does not establish readability of every real enrollment image or constitute a camera trial.

Camera tests replace acquisition and video-frame delivery with explicit fixtures, then exercise the real raster, worker, parser and OTP path. They verify no automatic acquisition, audio false, rear-camera preference, track cleanup, late permission, cancellation/reset/edit/close/background, permission/device errors, disconnect, deadline and non-TOTP payload rejection. The Windows WebKit automation build lacks MediaDevices and MediaStream, so these boundaries are explicitly supplied by the fixture rather than mistaken for native camera support. A separate local Chromium run uses its native getUserMedia API with a fake video device containing public QR frames. Neither establishes physical phone camera quality, autofocus or real permission UI behavior.

Unit tests check every RFC 6238 vector, RFC 4226 counters, leading zeroes, post-2038 counters, Base32 padding and canonical bits, parsing failure modes, period boundaries, offsets and an independent HMAC reference.

Sharing tests cover RFC 4648 export vectors, a separate encoding reference, bounded round trips, all setting combinations, corrupt/noncanonical/Unicode inputs, duplicate/missing/unknown fields and versions, non-HTTPS exports, exact link contents without label/offset/query, clipboard denial/unavailability, stale callbacks, tab hide, import/locale redirect, URL scrubbing, no secret in browser requests/storage, offline calculation and empty reload. Browser checks retain text-field semantics and CSS masking, with keyboard reveal/reset. An automated attribute check does not prove that every third-party password manager will suppress UI.

Browser tests run production HTML with its CSP in Chromium, Firefox and WebKit. Fixtures check automatic calculation and rollover, masking, inline validation/recovery, reset, settings import, no requests/storage during input, loaded-page operation offline, clipboard success/failure, delayed cryptography after Clear, script-unavailable initial controls, keyboard radios, forced colors and persisted optional themes.

Responsive coverage includes both locales/themes at 320, 360, 390, 600, 759, 760, 761, 768, 1024 and 1440 CSS pixels, with 200% text at 320. The standard five viewport families, breakpoint neighbors, open disclosures, scroll to final content and actual control inventory are covered. InspectInterface, inspectControlSurfaces and inspectHeaderBrand run on initial and populated states. Dropdown indicators are NOT_APPLICABLE because no dropdown exists. Axe provides partial automated accessibility coverage at mobile and desktop sizes.

Screenshots and traces live under ignored output/. Screenshots must be opened before reporting visual verification. Synthetic clipboard paths do not establish native clipboard permissions for every platform. Real physical devices, screen readers, field performance and an independent SI-agent trial are NOT_RUN unless separately observed.
